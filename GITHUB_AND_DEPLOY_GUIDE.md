# Publish Touch Grass (student-friendly checklist)

## Before pushing code

1. Run the app locally and generate at least one real plan using the exact open-weight model you intend to mention in your write-up.
2. Ensure you did not put an API key into any source file or screenshot. This app's `.gitignore` excludes `.env`, but do not create a hard-coded key in `app.py` or JavaScript.
3. Keep `SUBMISSION_DRAFT.md` as a draft until you replace the demo and GitHub placeholders and verify every claim.
4. Confirm the Hacktoberfest Week 1 new-project eligibility rule. The official page says the project and repository must be started and completed during the challenge window. A redesign of a project made for another event may not qualify; ask the organizers if unsure.

## Create a public GitHub repository

1. Sign in to GitHub and create a **new public repository** named `touch-grass-outdoor-guide`.
2. Do not initialize it with an extra README or license, because this project folder already contains a README.
3. In VS Code, open this extracted project folder and select **Terminal → New Terminal**.
4. If Git is installed, run the following commands. Replace `YOUR_GITHUB_USERNAME` with your actual username.

```powershell
git init
git add .
git status
git commit -m "Build Touch Grass Outdoor Guide"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/touch-grass-outdoor-guide.git
git push -u origin main
```

Check the `git status` output before committing. Never commit any `.env` file, API key, password, or private data. If `git remote add origin` reports that `origin` already exists, run `git remote -v` and update the URL rather than adding a second remote.

## Deploy through Render (optional)

This folder contains `render.yaml` and `Procfile` to make deployment simpler.

1. Push the project to your public GitHub repository first.
2. Sign in to Render and choose the Blueprint/new web-service flow for that repository.
3. Let Render read `render.yaml`, review the build/start commands, and start deployment.
4. Open the deployed URL and check `/api/health`. It should return JSON with `"ok": true`.
5. Test live weather, park search and a real AI request on the deployed website. If anything fails, inspect Render's logs and correct it before publishing the URL.

Deployment depends on your own GitHub and Render accounts. The project files do not create accounts or publish the site by themselves. A public deployment is not offline: weather, map tiles, and hosted AI all require internet.

## Screenshots / demo video

Capture the running app itself, not only the included AI mockups:

- Home dashboard and outdoor score
- AI plan generated by the chosen model (keep the API key hidden)
- Nearby parks map
- Nature Bingo or progress tracking

A short screen recording can show changing the city/activity, generating a plan, and then the screen-free challenge. Do not claim you physically tested the outing unless you actually did.
